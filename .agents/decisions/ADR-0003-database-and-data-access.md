# ADR-0003: Neon Postgres (London) with Drizzle ORM and reviewed SQL migrations
## Status
Accepted (Ashley Oliver, 2026-10-05)
## Context
- PostgreSQL is a stated preference.
- Data is relational and owned per user.
- The owner prefers staying close to SQL.
- Near-£0 cost.

Facts verified 2026-10-05, Neon Free:
- Per project: 1 GB storage, 100 CU-hours/month, 10 branches, 5 GB egress.
- Scale-to-zero after 5 minutes idle.
- 6-hour restore window.
- No commercial restriction stated.
- Limits suspend compute or block writes; data is never deleted.
- London region (`aws-eu-west-2`) is available.
## Decision
- Database: Neon Postgres, Free plan, London region. The production database lives on the main branch. Preview deployments and CI use short-lived Neon branches, deleted when the PR closes.
- ORM: Drizzle, with the schema defined in TypeScript.
- Migrations: generated by `drizzle-kit` as SQL files, reviewed as SQL in the PR and committed.
  - `drizzle-kit push` is never used against any shared database.
  - Migrations are applied by CI before the deployment that needs them.
  - Migrations must be backward-compatible with the running version (expand, then contract).
- Ownership convention: every user-owned table has a non-null `user_id`. Data-access functions in `src/server/` take the acting user's id and scope every query by it.
- Local development and CI tests use a real Postgres (Docker locally, a service container in CI). Tests don't run against Neon production.
- Backups beyond Neon's 6-hour window are delivered in F1, before real opportunity data is relied on.
## Why
- Drizzle is SQL-shaped, has no codegen step or engine binary, is serverless-friendly, has a Better Auth adapter, and produces reviewable SQL migrations.
- Neon offers scale-to-zero free Postgres in London, with branching that suits preview deployments.
## Alternatives considered
### Prisma
Mature migrations and excellent documentation. Rejected: its own schema language and a generated client sit further from SQL, and it adds a codegen step.
### Supabase Postgres
Free, but projects pause after inactivity and it pulls toward a BaaS coupling. Rejected.
## Consequences
- Drizzle has more churn between major versions, so versions are pinned and upgrades are deliberate.
- Column renames may need hand-edited migrations.
- Cold starts after 5 minutes idle add a small first-request delay.
- The 10-branch limit means preview branches must be cleaned up automatically.
